# История проекта SAS → SQL

История восстановлена по переписке, датированным техническим запискам, сохранённым отчётам, Git и артефактам запусков. Для ранних обсуждений доступна последовательность решений. Воспроизводимой сборки и измерений для каждого раннего шага нет. Отчёты разных этапов меняли корпус, правила сравнения и единицу подсчёта. Их результаты приведены с исходными знаменателями.

## Октябрь 2026. От идеи до нового ядра

| Этап | Запрос и решение | Что осталось от этапа |
|---|---|---|
| Первоначальная идея | Перенос всего процесса SAS Enterprise Guide в Greenplum, PostgreSQL и ClickHouse. Пользователь загружает EGP, уточняет структуру и утверждает план, затем согласует код и результаты проверки | Макеты четырёх экранов и двух гейтов. Приоритет Greenplum как DWH. Главная метрика - совпадение SQL-результата с исходной логикой |
| Детерминированный прототип | Разделять программы по конструкциям SAS и сохранять макросы и DATA STEP целиком. Изучены оболочки PROC, RUN, QUIT, присваивания и IF, преобразования, форматы и зависимости | Появился разбор блоков и набор правил. На реальных примерах обнаружились сокращение черновика, потеря модулей и значений. Полнота перевода на этом этапе не подтверждена |
| Словарь и план M01-M56 | Из EGP собрали шаблоны «SAS → SQL». Excel рассматривался как источник правил. Пользователь выбрал встроенный машиночитаемый словарь и единственный вход EGP. План шёл от правил и разбора к общей семантике и адаптерам | Встроенные правила остались частью backend. Сверка всего словаря по данным была недоступна без исходных эталонов и целевых стендов. Нумерация M01-M56 отражает объём плана, а не сертификат выполнения |
| Разбор сложных случаев | Проверялись макроподстановки, IF, форматы, DATA STEP, зависимости между программами и подключения. LIBNAME отложен как отдельная область согласования источников | Фиксированный запуск с заданными параметрами отделили от регулярного процесса. Для регулярного процесса с динамическими макросами требуется отдельный контракт исполнения |
| Выбор архитектуры | Обсуждались прямой OpenAI-compatible API, вызов Langflow по API, ручной обмен заданиями через интерфейс Langflow, исполнение внутри Langflow, эксперименты в Langflow с переносом в backend и помощь Codepilot при разработке правил | Выбран локальный backend с прямым API. Разбор, ручные соответствия источников, ревизии и проверка остаются в приложении. Внешний вызов управляется профилем. Для корпоративной эксплуатации предусмотрен корпоративный endpoint |
| 28-31 октября | Зафиксированы архитектура API, UX замены источников и план V2. В отдельном дереве начата реализация исходников без потери текста, явных привязок и проверки кандидатов | Ранняя Git-история V2 подтверждает снимок старых исходников и первую реализацию. Пользовательские макеты и локальные материалы старого ядра остались отдельными |
| Windows-поставка | Запрошен EXE с зависимостями и локальной обработкой. Отдельно разобрана проблема импорта, когда экран показывал выбранный EGP, а действие его не принимало | Появились изолированные сборки, локальные проверки импорта и тестовый EGP. Поздние smoke-прогоны проверяют этот маршрут |
