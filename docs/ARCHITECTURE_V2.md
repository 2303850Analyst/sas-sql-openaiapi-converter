# Архитектура SAS → SQL V2

V2 принимает EGP и локально строит список исходников, зависимости и задачи конвертации. В рабочей ревизии пользователь подтверждает порядок запуска, источники, параметры, типы, выходы и допустимые операции. После гейта 1 эти условия становятся контрактом.

Для каждого блока и целевой СУБД генератор OpenAI-compatible API получает согласованный контекст. Детерминированные правила могут выполнить отдельные преобразования, например точный десятичный AVG в ClickHouse при известном контракте. Статическая проверка контролирует допустимые конструкции SQL, зависимости, типы и обязательные выходы. Второй профиль модели ревьюит смысл блока и сборку сценария.

Для Greenplum доступно исполнение точных байтов экспорта под тестовой ролью с откатом. Перед гейтом 2 можно потребовать проверку физической схемы и сравнение всех выходов с независимым контролем. Исполнение, сравнение данных и ревью кода имеют самостоятельные свидетельства. Смена правил проверки помечает прежнее ревью неактуальным, сохраняя SQL и историю. Неподтверждённые сценарии остаются черновиками.

| Компонент | Ответственность |
|---|---|
| `sources.py`, `context.py`, `task_planner.py` | Разбор EGP, входы, обязательства и зависимости |
| `contracts.py`, `destinations.py` | Контракт типов, источников, выходов и режима Testifier |
| `ai_pipeline.py`, `numeric_rules.py`, `linker.py` | Генерация, типизированные преобразования, статическая проверка и ревью |
| `workflow.py`, `verification.py`, `rule_identity.py` | Ревизии, гейты и актуальность свидетельств |
| `server.py`, `web/`, `desktop_v2.py` | Локальный интерфейс и Windows-запуск |
