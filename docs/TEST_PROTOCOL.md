# Протокол проверки SAS → SQL V2

| Уровень | Что фиксируется | Критерий |
|---|---|---|
| Исходник | Хеш EGP, исходный текст, порядок программ, внешние зависимости | Каждый нужный исходник доступен либо исключён из согласованного объёма |
| Гейт 1 | Ревизия, параметры, соответствия источников, схемы и типы, порядок, выходы, разрешённые операции | Пользователь согласовал конкретный контракт. По неизвестным источникам и параметрам есть точный запрос |
| Кандидат | Диалект, хеш SQL, покрытие обязательств, статические замечания, настройки и вердикт независимого ревью | Совпадают область записи, зависимости, выходы и контракт. Проверка актуальна для ревизии и отпечатка правил |
| Исполнение | Версия движка, хеш исполняемого SQL, входы, результат каждого выхода | SQL выполнен в согласованной последовательности и с тестовыми правами |
| Сверка | Эталон, версия политики, схема, строки, дубли, значения, пропуски | Совпали все оговорённые результаты. Известное расхождение снимает допуск |
| Гейт 2 и экспорт | Согласование, область пакета, хеши манифеста и SQL | Согласован актуальный кандидат для заявленной области. Выпуск одного диалекта фиксирует свою область явно |

Гейт 2 по коду и нативное исполнение учитываются раздельно. Для утверждения эквивалентности в отчёте перечисляются фактически исполненные профили.

## Подготовка

1. Зафиксировать ревизию, версии движков, отпечаток правил и профили. До отправки модели заморозить корпус и независимые ожидания. Включить обычные, крайние, пустые и закрытые наборы. Закрытые результаты остаются у проверяющего.
2. Использовать изолированный стенд и синтетические проекты. Для Windows сравнить хеш EGP до и после пересборки. Сопоставить EXE с коммитом. Отдельно отметить ручные SQL-контроли и диагностические правки.
3. По каждому запросу фиксировать причину, хеш, фазу, исход, время, входные и выходные токены, учтённую сумму или резерв. При повторе тех же SQL, контракта и замечания остановить цикл. Ключи и сырые сетевые журналы остаются локально.

## Контрольные маршруты

| Шаг | Положительная и отрицательная проверки | Что сохранить |
|---|---|---|
| A. Импорт и UI | EGP открывается, оригинал доступен, перезагрузка возвращает ревизию. Пустой ввод, неверный файл и отсутствие параметра дают точные ошибки | Тесты, HTTP-результаты, браузерные действия |
| B. WORK и Testifier | WORK и выход без библиотеки дают TEMP. Явный адрес может сменить схему и хранение. `_test` меняет постоянные выходы и последующие ссылки. Смена адреса снимает согласование. Проверить конфликт, повторный суффикс и неизменность оригинала | Физический план, реестр `temporary/`, readback оригинала и тестовой таблицы |
| C. API и ревизии | Настроить профиль и перезапустить EXE. Проверить каталог, ручной ID, probe, DPAPI и ключ на сессию. На заглушке проверить ошибки HTTP, редирект, тайм-аут, TLS и DNS. Смена ключа и смена проверяющего дают разные переходы | Отдельные результаты заглушки и реального запроса, инвалидация ревью, сохранение байтов |
| D. Генерация | Проверить все программы, выходы и обязательства. Пропуск шага, неожиданный источник, неверная цель или неподтверждённый тип должны остановить выпуск | Замечания статики, ревью, история кандидатов и причина остановки |
| E. Нативное выполнение | Исполнять точные байты из ZIP. Для TEMP использовать одну сессию. Сверить все выходы. Удалить строку после 5 001 в контрольном варианте и подтвердить отказ | Версии движков, хеши, исход выполнения, типизированный полный readback |
| F. BI | Сверить сырые выходы с эталоном и прочитать строки запроса BI. Проверить фильтр, пустой набор, дубли, NULL и крупные десятичные числа | Результаты запросов, агрегаты, экран с фильтром. Числовое и текстовое представление фиксируются отдельно |
| G. Выпуск | Утвердить актуальный объём профилей. Проверить полный ZIP и ZIP одного согласованного диалекта. Сверить хеш SQL с исполненным | Манифест со статусом и областью. Нативное подтверждение для каждого доступного движка |

## Сравнение значений

- Сначала проверяются столбцы, типы, количество и кратность строк. Если порядок незначим, сравнивается мультимножество. Для порядка `BY`, накоплений и очереди `LAG` проверяются предусмотренные контрактом порядковые зависимости.
- Отдельно записываются точное совпадение и совпадение по [политике](../fixtures/testifier_lab/comparison_policy_v2.json). Три десятичных знака и `ROUND_HALF_UP` относятся к QA. Вычислительный тип, масштаб записи и представление при сравнении задаются раздельно. BI получает исходные значения. Даты и точная полночь сравниваются по контракту. Ненулевое время и пропуск проверяются отдельно.
- Для AVG, SUM и накоплений проверяются граница округления, пустая группа, все значения NULL и большие числа. Для JOIN и MERGE проверяются непарные ключи, дубли и пропущенные BY-ключи. Для строк проверяются пустое значение, пробелы, ширина поля.
- На синтетике основной эталон - независимый контрольный расчёт. OpenSAS даёт отдельную проверку поддержанных конструкций. Ошибка интерпретатора учитывается отдельно. Для реальной приёмки нужны согласованные выгрузки SAS Institute на тех же входах и параметрах.

## Воспроизведение без модели

~~~powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --no-index --find-links vendor/wheelhouse --require-hashes -r packaging_v2/requirements-test.lock
.\.venv\Scripts\python.exe -m pytest tests_v2 -q --junitxml=synthetic-results.xml
~~~

Для пяти контейнерных регрессий PostgreSQL использовать [локальный стенд и настройки](../fixtures/v2_pilot/README.md). CI пропускает эти регрессии без стенда. Testifier и BI используют [отдельную лабораторию](../fixtures/testifier_lab/compose.yaml) и [скрипты](../TESTIFIER.md). Compose ожидает закреплённые образы. Доступны [расширенный корпус](../expansion/corpus), [манифест](../expansion/synthetic_corpus_manifest.json) и [результаты базового прогона](../expansion/results/scenarios.csv).

В итоговом протоколе раздельно указываются прочитанные EGP, согласованные планы, принятые проекты, проверенные профили, запущенные наборы и несовпадения. Для сравнения версий нужен одинаковый корпус или сохранённый кандидат с одним контролируемым изменением.
