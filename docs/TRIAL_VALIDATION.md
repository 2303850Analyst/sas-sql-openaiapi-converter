## Старые дефекты и адресные проверки

| Дефект и влияние | Что изменили | Доказательство |
|---|---|---|
| ClickHouse заменял пропущенный месяц на 1970-01-01, а отсутствующий сегмент на пустую строку. Группы и суммы распределялись неверно | В поддержанных LEFT JOIN, прямых проекциях и выражениях дат правило сохраняет Nullable. Фильтр доказывает непустоту только при допустимой логике, включая отрицание OR. Меняется физический DDL, SELECT остаётся тем же | Старый сохранённый кандидат отклонялся по `month`, `segment`, `total`. После адресного правила на том же сохранённом сценарии **5/5** наборов по всем выходам. Свежий полный flow остаётся частичным |
| Ревью могло отклонить обычный ClickHouse Integer из-за отсутствия явного NOT NULL. Ошибка блокировала APPEND FORCE | Контракт и ревью уточнили с учётом обычного non-nullable типа ClickHouse | `ex_library` дошёл от закрытого до открытого гейта 2. Greenplum сохранил прежний хеш, PostgreSQL и ClickHouse прошли с новыми кандидатами модели. Обе нативные сверки **4/4** |
| ClickHouse AVG над Decimal терял разряды в Float64. Поздний CAST не восстанавливал точность | Узкое правило для типизированного случая использует точную сумму, безопасный делитель, промежуточный масштаб и округление перед записью | Предыдущий контроль на границе **4/5 → 5/5** на кейс. Сохранённый типизированный кандидат в расширении **4/4** после правила без новой генерации. Это регрессия предшествующей серии |
| Выборка с ограничением могла скрыть пропущенную строку в конце | Применено полное типизированное чтение выходов | Нативно прочитаны **5 002** строки в PostgreSQL и ClickHouse. Отрицательный контроль с отсутствующей последней строкой отклонён обоими |
| Предыдущее ревью могло оставаться действительным после смены правил | Ревью закреплено содержательным отпечатком, проверка данных - отдельным хешем политики | При смене правил прежний выпуск требует актуального ревью. Повторная генерация не нужна, если смысловой контекст и кандидат сохранены |
| Windows checkout менял окончания строк. Пересобранный EGP получал другой хеш, останавливая допуск синтетического профиля | `.gitattributes` и канонический LF при упаковке синтетического EGP | Неуспешный CI [42771643667](https://github.com/2303850Analyst/sas-sql-openaiapi-converter/actions/runs/42771643667). Повтор после `2c4e6ad` - **194 прошли, 5 пропущены**, [журнал CI](https://github.com/2303850Analyst/sas-sql-openaiapi-converter/actions/runs/42771877258) |

## Матрица последнего прогона

| Сценарий | Гейт 2 до → после | PostgreSQL | ClickHouse | Что осталось |
|---|---|---:|---:|---|
| `trial_multiset` - UNION ALL | Да → да | 3/3 | 3/3 | Подтверждены кратность строк и те же байты после перепроверки |
| `ex_library` - APPEND FORCE | Нет → да | 4/4 | 4/4 | Подтверждены схема BASE, дубли, типизированные пропуски и BI |
| `ex_dispatch` - макропорог, два выхода DATA STEP и LEFT JOIN | Нет → нет | Нет прогона | 3/3 | PostgreSQL и Greenplum не получили принятого кандидата. Неверные столбцы/таблицы и остановка повторов |
| `trial_options` - KEEP/WHERE/RENAME | Нет → нет | Нет прогона | Нет прогона | `MISSING_RENAME`, `column_resolution_failed`, неполный выход, повтор без прогресса |
| `trial_unknown_array` | До API остановлен на гейте 1 | Нет прогона | Нет прогона | Ожидаемый отказ `external_parameter_required` для границы массива |
| `flow` - полная цепочка | Нет → нет | 5/5 | Нет свежего принятого прогона | Сохранённый контроль Nullable **5/5** отдельно. Свежий маршрут не закрыл `monthly` и десятичный контракт |
| `flow` после уточнения контракта | Нет → нет | 5/5 | Нет прогона | Greenplum и PostgreSQL прошли ревью. Следующая попытка ClickHouse не вместилась в общий лимит |

`ex_dispatch` принимался на предыдущей ревизии из расширенного корпуса. В свежей генерации пробной сборки сохранился только прошедший ClickHouse-профиль. Это зафиксированный пример того, что успешная старая ревизия не гарантирует успешную повторную генерацию.
