# Пробная поставка SAS → SQL V2

1. Распакуйте ZIP в отдельную папку и запустите `Start-Trial.cmd`. Он откроет локальный интерфейс в отдельном профиле данных. Для запуска под Windows x64 Python, Node и Docker не нужны.
2. Откройте **Настройки → Подключение к ИИ**. Укажите имя, корпоративный Base URL с полным префиксом пути либо полный адрес `…/chat/completions`. Проверьте конечный адрес после сохранения.
3. Введите ключ в отдельное скрытое поле. Выберите защищённое сохранение через Windows DPAPI или хранение в памяти до закрытия программы. Удаление ключа задаётся отдельно. Для сервера без авторизации выберите соответствующий режим.
4. Выберите подтверждённый режим тарификации. При корпоративном подключении явно согласуйте отправку кода на указанный сервер. Для платного профиля нужны ставки и бюджет. В режиме неизвестного тарифа можно узнать список моделей, а платный или корпоративный вызов требует явного выбора режима.
5. Получите модели или введите точный ID вручную. Проверяющий по умолчанию использует ту же модель отдельным вызовом. Кнопка **Проверить соединение** отправляет короткий синтетический запрос. При ошибке каталога ручной ID остаётся доступен.
6. Загрузите EGP. Для первого прохода возьмите `demo/ex_library.egp` или `demo/trial_multiset.egp`. Проверьте порядок, назначьте входные таблицы и подтвердите выходы, типы, параметры и тестовый режим. Утвердите гейт 1.
7. Выберите подключение в разделе генерации и запустите SQL. Просмотрите результаты по целевым профилям. После устранения блокировок утвердите гейт 2 и скачайте весь проект либо выбранный профиль.

Ключ и настройки хранятся в пользовательском каталоге `SasSqlMigrationV2-Trial` при запуске через `Start-Trial.cmd`. Перед сменой адреса с сохранённым ключом приложение требует явную замену или удаление ключа. TLS проверяется, при необходимости укажите корпоративный CA и явный proxy. Публичный резервный endpoint отсутствует.

Гейт 2 принимает проверенный код. Сверка результата на данных проводится отдельно. Для проверки всех обязательных выходов используйте один непрерывный сеанс на целевой СУБД и согласованные синтетические входы. При неполной приёмке ZIP явно отмечает статус и объём экспорта.
